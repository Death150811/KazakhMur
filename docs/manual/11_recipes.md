# Часть III. Рецепты и решения

## 11. Рецепты: как сделать типовую работу

Каждый рецепт — последовательность шагов, проверенная на практике в этом проекте. Если рецепт затрагивает язык, помните
правило «**оба движка**» (глава 6).

### Рецепт 1. Добавить встроенную функцию

1. **Python** — в нужный файл `qaz/stdlib/*.py`:

```python
from qaz.stdlib.registry import builtin, expect_number

@builtin("квадрат", 1, 1, category="math", sig="квадрат(x)", doc="Квадрат числа.")
def _square(interp, x):
    x = expect_number("квадрат", x)       # понятная ошибка, если не число
    return x * x
```

2. **JS** — в `site/src/engine/04_stdlib.js` (имя и арность те же; `BigInt` для целых!):

```js
def('квадрат', 1, 1, (it, x) => { expectNumber('квадрат', x); return typeof x === 'bigint' ? x * x : x * x; });
```

3. Если нужны именованные аргументы: `kw=("а", "б")` (позиционные с именем) или `kwonly=("кілт",)` (только по имени; в JS такая
   функция получает **последним аргументом объект** `{кілт: значение}` — см. `сұрып`, `минимум`).
4. Тест на Python (`tests/test_stdlib.py`) + программы в `tests/conformance_corpus.py` (в том числе с ошибками в `байқа`).
5. Новые тексты ошибок → `qaz/messages_kk.json` (тест `test_messages` перечислит недостающие).
6. `python3 scripts/gen_stdlib_doc.py`, `python3 scripts/build_site.py`; запустить `python3 -m pytest`.
7. CHANGELOG; при необходимости — упоминание в `book.json` (счётчики обновятся сами).

### Рецепт 2. Добавить метод встроенного типа

Python: `@method(list, "имя", мин, макс, sig=".имя(…)", doc="…")` (первый параметр функции после `interp` — сам объект).
JS: `method('list', 'имя', мин, макс, (it, объект, …аргументы) => …)` (виды: `str`, `list`, `dict`, `tuple`, `set`).
Новый тип значения (как `жиын`) — это уже **рецепт 5**: нужны класс значения, `type_name`, `to_repr`, равенство, перебор, оператор
`ішінде`, `as_list`, длина, таблица методов и сообщения.

### Рецепт 3. Добавить ключевое слово

1. `qaz/tokens.py`: запись в `KEYWORD_INFO` (аналог и пояснение); синоним — в `KEYWORD_ALIASES`.
2. Лексер сам пометит слово как `KW`. Парсер: метод `parse_*` и ветка в `parse_statement` (`qaz/parser.py`).
3. AST: класс в `qaz/ast_nodes.py`; интерпретатор: запись в `_ex`/`_ev` и метод.
4. JS: `T`-константы не нужны (слова берутся из `LANG.keywords`), но парсер, `runStmt`/`evaluate` — обязательно.
5. Сайт: подсветка и автодополнение берут слова из `LANGUAGE` — **автоматически**; таблица слов — тоже. Проверить e2e (`#kwBody tr`: число
   строк — **22**, обновить).
6. Грамматика (`docs/GRAMMAR.md`), синтаксис (`docs/SYNTAX.md`), корпус, юнит-тесты, CHANGELOG.
7. ⚠ Новое ключевое слово **ломает программы**, где так названа переменная. Обсудите с владельцем (это решение про язык).

### Рецепт 4. Добавить синтаксическую возможность (оператор, форма выражения)

Пример — оператор конвейера `|>` (коммит «особенности языка»). Шаги: (1) лексер: токен (`OPERATORS_2`), (2) парсер: уровень
приоритета в цепочке `parse_*`, (3) AST-узел, (4) Python-интерпретатор, (5) тот же путь в JS, (6) подсветка в `site/src/app.js: tokenize`
(если токен новой формы), (7) корпус программ в обоих движках, включая ошибки, (8) документация (SYNTAX, GRAMMAR), (9) тур/книга при
необходимости.

### Рецепт 5. Добавить новый тип значения

Образец — `жиын` (коммит «Множества»): Python `QSet` в `runtime.py` (`type_name`, `to_repr`, `to_str`); `as_list`, `ұзындық`,
перебор в `x_for`/`_run_comp`, оператор `ішінде` в `compare`, `METHODS`; JS `QSet` в `02_values.js` + `typeName`, `truthy`, `toRepr`,
`toStr`, `valuesEqual`, `QDict.keyOf` (запретить как ключ), `asList`, перебор, `ішінде`, `methodTable`. Решите: можно ли
использовать как ключ (обычно нет), порядок перебора (детерминированный!), сравнение. Затем корпус + юнит-тесты + каталог сообщений.

### Рецепт 6. Добавить или изменить сообщение об ошибке

1. Создайте ошибку в коде как обычно (`QazaqRuntimeError("…", hint="…")` или `rt_error`), по-русски, с f-строкой для значений.
2. Запустите `python3 -m pytest tests/test_messages.py` — тест покажет, чего не хватает.
3. Добавьте пару `[русский шаблон с {именами}, казахский]` в `qaz/messages_kk.json`, **частные правила — выше общих**. Для «ожидалось … найдено …»
   новые описания добавляются в `fragments`.
4. `python3 scripts/gen_manual.py` обновит таблицу для проверки носителем.

### Рецепт 7. Добавить пример программы

`examples/NN_имя.qaz` (первая строка `# title: Название`; комментарии — `;`) и `examples/NN_имя.expected` с точным выводом. Пример
появится в списке на сайте, его прогонят e2e (в браузере), `test_integration` (против `.expected`) и тест соответствия. Научные примеры, которым
нужен SymPy, называйте с `science` в имени (они исключаются из сравнения в JS).

### Рецепт 8. Тема тура, карточка, глава и термин книги

См. таблицу 7.6. Главное: тексты двуязычные (`ru`/`kk`) в `tour.json`; в `book.json` — только русский; код в туре и «Попробуйте» исполняется тестами
в обоих движках, поэтому он обязан работать без ввода и внешних файлов.

### Рецепт 9. Подготовить релиз

1. Поднять версию: `pyproject.toml`, `qaz/__init__.py`, строка в `README.md`; запись в `CHANGELOG.md`.
2. `python3 -m pytest` (с `NODE_PATH`) — всё зелёное.
3. Проверить пакет: `python3 -m build` (нужен `build`), поставить колесо в **чистое** виртуальное окружение (`python3 -m venv /tmp/v && /tmp/v/bin/pip install
   dist/*.whl`), выполнить `qaz version`, `qaz run examples/01_hello.qaz`, `qaz check …`. (Так проверялась упаковка; тесты и сайт в колесо не входят,
   каталог сообщений `messages_kk.json` — входит через `package-data`.)
4. `python3 scripts/build_site.py`, перегенерировать PDF книги, опубликовать сайт.
5. Публикация на PyPI (`twine upload`) — **только владелец**, это его аккаунт и токен.

### Рецепт 10. Слить в `main` и включить Pages (только с разрешения владельца!)

1. Получить явное «да» владельца. Не обходить блокировку классификатора.
2. Создать `main` из `claude/qazaq-lang` (например через Pull Request на GitHub — его создаёт владелец или по его просьбе исполнитель с `gh`).
3. В репозитории: Settings → Pages → Build and deployment → Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` запустится при пуше в `main`.
4. Проверить вкладку Actions и адрес в Settings → Pages. Если основная ветка называется иначе — поправить `branches:` в workflow.

### Рецепт 11. Перевести книгу и интерфейс на казахский

Интерфейс: добавить недостающие ключи в `I18N.kk` (`site/src/app.js`) — полный список ключей есть в `I18N.ru`. Книга: сейчас одно поле на
текст; нужно ввести двуязычные поля (`{ru, kk}`) по образцу `tour.json`, заменить `pick()` в `renderBook`, расширить `test_book`. Тексты **обязательно**
проверяет носитель.

### Рецепт 12. Проверить казахские тексты носителем

Отдайте `docs/KAZAKH_MESSAGES_REVIEW.md`. Правки вносятся в `qaz/messages_kk.json` (значение справа), затем `python3 scripts/gen_manual.py` и тесты. Подписи
интерфейса — в `I18N.kk` и в `tour.json` (`kk`).
