## 10. Документация как часть продукта

### 10.1. Инвентарь документов

| Документ | Для кого | Содержание | Как поддерживается |
|---|---|---|---|
| `README.md` | все | описание, быстрый старт, сайт, тесты, структура | вручную; блоки кода исполняются |
| `docs/SYNTAX.md` | пользователи языка | синтаксис с запускаемыми примерами (`qaz-run`) | вручную |
| `docs/GRAMMAR.md` | разработчики | формальная грамматика EBNF и правило точки | вручную |
| `docs/STANDARD_LIBRARY.md` | пользователи | справочник функций и методов | **генерируется** (`scripts/gen_stdlib_doc.py`) |
| `docs/ERRORS.md` | пользователи | виды ошибок, формат, коды завершения, язык сообщений | вручную |
| `docs/ARCHITECTURE.md` | разработчики | модули, потоки данных, два движка | вручную |
| `docs/LANGUAGE_DESIGN.md` | владелец/разработчики | оценка ключевых слов, открытые вопросы | вручную |
| `docs/SECURITY.md` | эксплуатация | что защищено, что нет, рекомендации | вручную |
| `docs/DEPLOY.md` | эксплуатация | Pages, любой хостинг, серверный режим, пакет, чек-лист | вручную |
| `docs/ROADMAP.md` | все | что сделано / частично / планируется | вручную |
| `CHANGELOG.md` | все | история по версиям | вручную, после каждого этапа |
| `docs/MANUAL.md` | **продолжающий и человек** | это руководство | **генерируется** из `docs/manual/*.md` |
| `docs/KAZAKH_MESSAGES_REVIEW.md` | носитель языка | таблица казахских сообщений | **генерируется** |
| `docs/QAZAQ_BOOK.pdf` | человек | печатная «Книга» | генерируется Playwright |
| раздел «Книга» на сайте | человек | то же в интерактивной форме | `site/src/book.json` |

### 10.2. Правила

1. **Документация соответствует реализации.** Не описывайте то, чего нет. В `ROADMAP.md` чётко разделены ✅ реализовано,
   🟡 частично, ⬜ запланировано.
2. **Примеры кода в документации — работающие.** Помечайте блоки ```` ```qaz-run ```` (исполняются) или ```` ```qaz ````
   (только разбираются и всё равно сравниваются двумя движками). Не работающий пример → ```` ```text ````.
3. После правки реестра функций — `python3 scripts/gen_stdlib_doc.py`; после правки глав руководства или каталога сообщений —
   `python3 scripts/gen_manual.py`. Тесты напомнят, если забыли.
4. `CHANGELOG.md` — новая запись сверху секции текущей версии; формат — маркированный список «что изменилось для пользователя».

### 10.3. Как этот файл (MANUAL.md) устроен и обновляется

Руководство **собирается**, а не пишется в один файл: главы лежат в `docs/manual/NN_имя.md` (нумерация задаёт порядок), скрипт
`scripts/gen_manual.py` склеивает их и заменяет метки вида `{{ AUTO:имя }}` (в рабочих главах пишутся без пробелов внутри скобок) данными из кода:

| Метка | Что подставляется |
|---|---|
| `{{ AUTO:tree }}` | дерево файлов с назначением (назначения хранятся в словарях `PURPOSE` и `DIR_PURPOSE` внутри скрипта; для новых файлов добавьте строку) |
| `{{ AUTO:stats }}`, `{{ AUTO:tests }}`, `{{ AUTO:builtins_count }}` | числа и счётчики (при проверке актуальности игнорируются — они меняются при любой правке) |
| `{{ AUTO:keywords }}`, `{{ AUTO:builtins }}`, `{{ AUTO:methods }}` | таблицы из реестра языка |
| `{{ AUTO:trace_example }}` | настоящие токены и дерево для `жаз(2 + 3).` |
| `{{ AUTO:kw_count }}` | количество ключевых слов |

`tests/test_manual.py` проверяет: (1) собранный `MANUAL.md` совпадает с тем, что даёт скрипт (кроме «нестабильных» разделов);
(2) каждый путь вида `qaz/…`, `site/…`, `docs/…`, `tests/…`, `scripts/…`, `backend/…`, `examples/…`, упомянутый в тексте в обратных
кавычках, **существует**. Поэтому, переименовав файл, вы получите падение теста, пока не поправите руководство — это
сделано намеренно. **Редактируйте главы в `docs/manual/`, а не `MANUAL.md` напрямую.**
