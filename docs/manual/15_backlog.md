## 15. Известные ограничения, долги и план работ

### 15.1. С чего начать, продолжая проект

1. Прочитать главы 1–3 и 11 этого руководства; затем `docs/ROADMAP.md` и `CHANGELOG.md`.
2. `git status`, `git log --oneline | head`, убедиться, что вы в ветке `claude/qazaq-lang`.
3. `export NODE_PATH="$(npm root -g)" && python3 -m pytest` — убедиться, что всё зелёное **до** изменений.
4. Проверить, нет ли новых сообщений/решений владельца (в диалоге; комментарии к Artifact — через `ArtifactComments`).
5. Взять пункт из списка ниже (сверху вниз), работать по циклу из главы 2.3, после каждого этапа — коммит, пуш, публикация, короткий отчёт в 5 пунктов.

### 15.3. Технический долг (мелкие вещи, о которых стоит знать)

* `docs/ARCHITECTURE.md` написан раньше сайта; части про Playground/Monaco устарели (обновлено в этом коммите, но проверяйте).
* `site/src/app.js: renderEditor` содержит условие `if (lines.length !== ed.lines || true)` — осталось от прежней оптимизации; безвредно.
* Узел `Spread` не зарегистрирован в `Interpreter._ev` — он обрабатывается только внутри `e_call`; если используете его в другом месте, добавьте обработку.
* Ключ словаря `NaN`: в JS нормализуется в строку `fNaN` (все NaN — один ключ), в Python `nan != nan`. На практике не встречается; не «чинить», пока не нужно.
* e2e-тесты содержат русские фрагменты текста (`/готов/i`, «Остановлено»): при смене формулировок интерфейса обновляйте их.
* PDF книги хранится в git (≈ 1 МБ на версию) — перегенерируйте только при изменении текста; в будущем можно хранить в релизах, а не в репозитории.
* `qaz/messages_kk.json` — частично зависит от порядка правил; тест `test_no_rule_is_shadowed…` страхует.
* Тестовое окружение: `tests/test_site.py` запускает три тяжёлых Node-теста — если нужно быстрее, запускайте `-k "not site"`.
* Ветка `claude/push-check` на GitHub — мусор, можно удалить с разрешения владельца.
