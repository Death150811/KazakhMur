## 6. JS-движок и совпадение двух реализаций

### 6.1. Зачем два движка

Сайт должен работать **без сервера**, мгновенно и безопасно для публичного хостинга. Варианты были такие:

| Вариант | Почему отклонён / принят |
|---|---|
| Отправлять код на сервер с Python | нужен сервер и безопасная изоляция чужого кода; не работает без сети |
| Запустить настоящий Python в браузере (Pyodide) | десятки мегабайт загрузки, медленный старт, внешняя зависимость; сайт перестал бы быть одним лёгким файлом |
| **Переписать интерпретатор на JavaScript** | **принято:** страница ≈ 470 КБ, старт мгновенный, код не покидает устройство; цена — нужно поддерживать два движка одинаковыми |

Цена контролируется **дифференциальными тестами**: оба движка запускают одни и те же программы, и любое расхождение —
ошибка. Поэтому правило проекта: **любое изменение поведения языка делается в обоих движках сразу**.

### 6.2. Как собран JS-движок

Файлы `site/src/engine/[0-9]*.js` склеиваются **по алфавиту** (`scripts/build_site.py: engine_source`) в одно замыкание:

```js
function createQazaqEngine(LANG) {   // LANG = language.json, сгенерированный из Python-реестра
'use strict';
…все файлы подряд…
return { version, run, check, tokens, tree, trace, translateError, formatError, builtinNames, keywordNames };
}
```

| Файл | Содержание |
|---|---|
| `00_messages.js` | перевод сообщений об ошибках по каталогу (тот же алгоритм, что `qaz/messages.py`) |
| `01_lexer_parser.js` | лексер и парсер; ошибки; `formatError`; `parse(source)` |
| `02_values.js` | `Env`, `QFunction`, `QClass`, `QRange`, `QTuple`, `QDict`, `QSet`; `typeName`, `truthy`, `toRepr`, `toStr`; равенство и порядок (`valuesEqual`, `compareValues`); форматирование по мини-языку Python (`formatValue`); округление, деление, `fsum` |
| `03_interpreter.js` | интерпретатор (порт `qaz/interpreter.py`) + хук `onStep` для вкладки «Шаги» |
| `03b_hpmath.js` | `sin/cos/tan/log/pow` на `BigInt` с фиксированной точкой (192 бит) и корректным округлением |
| `04_stdlib.js` | `PyRandom` (Mersenne Twister), `def(...)` встроенных функций, `method(...)` методов, точная сумма и дисперсия |
| `04b_symbolic.js` | `шеш/туын/интегр` для многочленов на точных дробях, вывод по правилам SymPy |
| `05_api.js` | самопроверка реестра, `runProgram`, `checkProgram`, `tokensOf`, `treeOf`, `traceProgram` |

⚠ **Порядок файлов важен**: в замыкании функции видят друг друга, но `const`/`class` из более позднего файла не
доступны во время выполнения кода верхнего уровня раньше файла. Новые файлы называйте с правильным числовым префиксом.

### 6.3. Модель значений JS и подводные камни

* `бүтін` = `BigInt` (всегда!); `нақты` = `number`. Смешанная арифметика (`1 + 1.5`) обрабатывается явно. Никогда не
  смешивайте `BigInt` и `number` в JS-выражениях — будет `TypeError`.
* **Печать дробных** (`floatRepr`) повторяет `repr` Python: кратчайшая запись, которая читается обратно в то же число;
  `1e+16`, `1.5e-07`, `0.30000000000000004`.
* **Форматирование** `{x:.2f}`, `{n:,}`, `{x:e}`, `{x:g}`, `{n:#x}` и т. д. реализовано **точными** вычислениями на `BigInt`
  (округление к чётному по двоичному значению, как в Python): иначе `{2.675:.2f}` дал бы другое число.
* **Округление** `дөңгелекте` — «по-школьному» (0,5 вверх) через десятичное представление (`roundHalfUp`), как в Python-версии.
* **Математика:** встроенные `Math.sin/Math.pow` в V8 отличаются от libm в последнем бите в 4–7 % случаев, поэтому
  `03b_hpmath.js` считает на `BigInt` и округляет до ближайшего. Оставшиеся расхождения — менее 0,2 % значений и только
  там, где сама libm округляет не к ближайшему. Тесты сравнивают дробные результаты тригонометрии после `дөңгелекте(…, 8)`.
* **Случайные числа:** `PyRandom` — Mersenne Twister, совместимый с `random.seed(int)` Python: `тұқым(42)` даёт те же
  числа на сайте и локально.
* **Строки:** длина и индексы — по **символам Unicode** (`strChars`, `strLen`), а не по кодовым единицам UTF-16
  (иначе смайлик «😀» считался бы за 2).
* **Словарь и множество** (`QDict`, `QSet`): ключи нормализуются в `QDict.keyOf` так, чтобы `1`, `1.0`, `ақиқат` были одним
  ключом (как в Python); изменяемые значения (тізім, сөздік, жиын) в ключ не принимаются (`Unhashable`).
* **Стек JS меньше стека Python:** глубина вызовов на сайте ограничена **200** (Python — 1000, Playground — 300); при
  реальном переполнении стека (`RangeError`) движок возвращает понятную ошибку (`isStackOverflow`).
* **Хук трассировки:** `Interpreter.onStep(node, env)` вызывается перед каждой инструкцией, если задан; `frames` хранит
  имена активных функций. Используется только вкладкой «Шаги» (`traceProgram` в `05_api.js`).

### 6.4. Как устроен тест соответствия (`tests/test_conformance.py`)

Источники программ (`all_programs()`):

1. `tests/conformance_corpus.py` — словарь `PROGRAMS` (≈ 400 программ; добавляются вызовом `add(имя, код, stdin="")`);
2. все `examples/*.qaz` (кроме научного, требующего SymPy);
3. все блоки ```` ```qaz ```` и ```` ```qaz-run ```` из `README.md` и `docs/*.md`;
4. код карточек и тем тура из `site/src/tour.json`;
5. примеры «Попробуйте» из `site/src/book.json`.

Алгоритм: Python запускает программу через `qaz.runner.execute`, JS — через `site/test/run_corpus.js` (Node читает JSON
из stdin, прогоняет `engine.run`, пишет JSON). Сравниваются **вывод, статус, заголовок ошибки, сообщение, строка, столбец,
подсказка и трасса вызовов** — дословно. Ещё два теста: 4000 случайных выражений (генератор с фиксированным seed:
арифметика, сравнения, функции, срезы, форматы) и 400 случайных многочленов против SymPy для `шеш/туын/интегр`.

**Как добавить программу:** допишите `add("имя", "код")` в конец `tests/conformance_corpus.py`; полезно включать **ошибки**
внутри `байқа: … қате е: жаз(е).` — тогда сравниваются и тексты ошибок. После этого `python3 -m pytest
tests/test_conformance.py`. Если Python и JS расходятся, чините **JS**, если только Python-поведение не ошибочно (тогда
обе стороны).

⚠ Если в программе синтаксическая ошибка, оба движка тоже совпадут (оба сообщат об ошибке) — тест «зелёный», но
программа ничего не проверяет. **Смотрите вывод новой программы глазами**: запустите её через `qaz.runner.execute` и
прочитайте результат (так в этом проекте дважды ловились опечатки в корпусе).

### 6.5. Рецепт «добавить поведение в оба движка»

1. Python: изменить `qaz/…` (лексер/парсер/AST/интерпретатор/библиотека).
2. JS: изменить соответствующий файл в `site/src/engine/`. Имена методов и структуры повторяют Python (`x_vardecl` ↔
   `xVardecl`/`runStmt`, `parse_postfix` ↔ `parsePostfix`).
3. Если добавили встроенную функцию/метод — реализация в `04_stdlib.js` через `def(...)`/`method(...)`; описание уже
   пришло из Python-реестра через `language.json` (самопроверка при старте сообщит, если забыли).
4. Добавить программы в корпус (с ошибками), юнит-тест на Python.
5. Если появились новые сообщения об ошибках — добавить их в `qaz/messages_kk.json` (тест подскажет какие).
6. `python3 -m pytest` целиком; затем документация (глава 11).

### 6.6. Сознательные различия движков

| Что | Python | JS (сайт) |
|---|---|---|
| `шеш`, `туын`, `интегр` | SymPy: любые выражения | многочлены от одной переменной с целыми коэффициентами; остальное — понятное сообщение «нужен локальный Qazaq» |
| `сыз`, `оқы`, `сақта` | работают (`qaz run`) | недоступны |
| Максимальная глубина вызовов | 1000 (Playground 300) | 200 |
| Вкладка «Шаги» | нет | есть |
| Скорость | `fib(24)` ≈ 0,6 с | ≈ 0,5 с; циклы заметно быстрее |
