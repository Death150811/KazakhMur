## 5. Устройство интерпретатора (Python-версия)

Путь программы: **текст → лексер → токены → парсер → AST → интерпретатор → результат**. Каждый шаг — отдельный
файл с одной ответственностью (так требовало задание).

### 5.2. Лексер (`qaz/lexer.py`)

**Вход:** строка исходника. **Выход:** список `Token(kind, value, line, col, end_line, end_col)`; виды токенов — в
`qaz/tokens.py`: `INT FLOAT STR FSTR NAME KW OP DOT END NL INDENT DEDENT EOF`.

Что делает по порядку:

1. **Подготовка текста:** отбрасывает BOM, приводит `\r\n`/`\r` к `\n`. (NFC применяется не ко всему тексту, а к
   **идентификаторам** — см. шаг 5; строки программы остаются такими, как их написали.)
2. **Главный цикл** (`tokenize`): в начале логической строки считает отступ (`_line_start`) и выдаёт `INDENT`/`DEDENT`;
   дальше пропускает пробелы, комментарии (`#` и `;` до конца строки), читает число/строку/идентификатор/оператор.
3. **Перевод строки.** `NL` выдаётся только если предыдущий токен — `END` или `:` и скобки закрыты (`self.brackets`
   пуст). Иначе перенос строки игнорируется — вот почему не нужны ни точки с запятой, ни символ продолжения.
4. **Числа** (`_number`): только ASCII-цифры (`²` и другие «цифры» Unicode — не числа; раньше они **роняли**
   интерпретатор, это нашёл фаззинг); `_` как разделитель; `.дробь`, экспонента; предел 150 000 цифр.
5. **Идентификаторы** (`_identifier`): буква или `_`, затем буквы/цифры/`_`/объединяющие знаки; затем **NFC** (чтобы «й» из «и» + знака краткости и «й» одним символом были одним именем); проверка
   **смешения латиницы и кириллицы** внутри одного слова (латинская `i` и казахская `і` — разные символы) с точным
   сообщением и номером символа; ключевые слова и синонимы превращаются в `KW` (синоним заменяется основным словом).
6. **Строки** (`_string`): `"…"`, `'…'`, `"""…"""`; escape-последовательности `\n \t \r \0 \\ \" \'`; форматная
   строка `ф"…"`: внутри `{выражение:формат}` (двойные `{{`/`}}` — литералы). Выражение вырезается как `FPart(source,
   spec, line, col, square)` и **разбирается позже парсером отдельным лексером** (`expr_mode=True`).
7. **Операторы** (`_operator`): двухсимвольные (`** // == != <= >= += -= *= /= |>`), математические знаки
   (`UNICODE_OPS`), точка/вопрос/восклицание (правило точки, см. 4.1), скобки со стеком `(символ, строка, столбец, как
   показано)`; незакрытая/лишняя скобка — ошибка с позицией.
8. **Режим «шаршы жақша»:** директива `;! жақша = шаршы` (или `#! brackets = square`) в первых строках файла
   (`read_pragma_square`) либо аргумент `Lexer(square=True)` меняют местами `( ) ↔ [ ]` на уровне лексера:
   парсер видит обычные скобки и ничего не знает о режиме. Для форматных строк флаг передаётся в `FPart.square`.

Все ошибки лексера — `LexicalError` (не ловится из программы), с позицией и, где можно, подсказкой.

### 5.3. Парсер (`qaz/parser.py`)

**Метод:** рекурсивный спуск (каждому правилу грамматики — метод `parse_*`). Вход — токены (и исходный текст — для
сообщений и для текста `?`/`!`-инструкций через `text_between`). Выход — `Program` (список инструкций).

* **Приоритеты** задаются цепочкой методов от слабого к сильному:
  `expr → ternary → pipe → or → and → not → comparison → add → mul → unary → power → postfix → primary`.
  `**` правоассоциативна; унарный минус слева применяется после возведения в степень (`-2 ** 2 = -4`).
* **Инструкции** (`parse_statement`): объявления, присваивания (в том числе множественные и составные `+=`),
  `егер/әзір/әрбір`, `функ`, `сынып`, `байқа`, `қайтар/тоқта/жалғас/өткіз/лақтыр`, выражение как инструкция.
  Конец простой инструкции проверяет `expect_end`: если вместо точки что-то иное — ошибка «Инструкция должна заканчиваться
  точкой» **в конце предыдущей строки** (так указание точнее).
* **Семантические проверки на этапе разбора:** `қайтар` вне функции, `тоқта`/`жалғас` вне цикла (счётчики
  `func_depth`/`loop_depth`), повтор параметров, параметр без значения после параметра со значением, неверная цель
  присваивания, ключевое слово как значение.
* **Защита от переполнения стека:** `MAX_NESTING = 60` — глубже вложенность выражений и блоков даёт понятную
  синтаксическую ошибку, а не падение Python (это тоже нашёл фаззинг).
* **Сообщения:** `expect(kind, value, what)` формирует «Ожидалось {что}, найдено {что нашли}». Поэтому в каталоге
  казахских сообщений есть отдельный список **фрагментов** для `{want}`/`{got}` (см. 5.7).

### 5.4. AST (`qaz/ast_nodes.py`)

Узлы — `@dataclass(slots=True)`, у каждого `line`/`col` (откуда берётся позиция ошибки). Классы: `Program`, инструкции
`VarDecl VarDeclMulti Assign ExprStmt If While For FuncDef ClassDef Return Break Continue Pass Raise Try`; вспомогательные
`Param` (`kind`: `""`, `"rest"`, `"kwrest"`), `TargetList`; выражения `Literal FString Name ListLit TupleLit DictLit
ListComp DictComp Unary Binary Logical Compare Call Ternary Pipe Lambda Index Slice Attr`, и `Spread` (только внутри
аргументов вызова). `Call.kwargs` — список пар `(имя, выражение)`; имя `None` означает `**словарь`.
`ExprStmt.mode` — `.`/`?`/`!`, `ExprStmt.text` — исходный текст выражения (для `?` и `!`).

### 5.5. Интерпретатор (`qaz/interpreter.py`)

* **Диспетчеризация по типу узла:** словари `_ex` (инструкции) и `_ev` (выражения) отображают класс узла в метод.
  Новый узел = класс в `ast_nodes.py` + запись в словаре + метод `x_*`/`e_*`.
* **Окружения** (`qaz/runtime.py: Env`): цепочка словарей. Корень — `builtin_env` (только чтение: попытка присвоить
  встроенному имени — ошибка), над ним `globals`. Вызов функции создаёт `Env(fn.closure)`.
* **Управление потоком:** `қайтар/тоқта/жалғас` реализованы внутренними исключениями `_Return/_Break/_Continue`; парсер
  гарантирует, что они не выйдут за функцию/цикл.
* **Позиции ошибок:** узлы знают `line/col`; исключение без позиции получает её у ближайшего узла при всплытии
  (`_locate`), поэтому встроенные функции позиций не заботятся. При выходе из функции к ошибке добавляется кадр трассы
  `(имя, строка вызова)`.
* **Лимиты** (`Limits`): `max_steps` (счётчик `_tick` на каждую инструкцию и вызов), `timeout` (проверка времени раз в 256
  шагов), `max_depth` (глубина вызовов), `max_output` (символы вывода). Превышение — `ResourceLimitError`, которую
  нельзя поймать. Дополнительно защита от «бомб»: `MAX_INT_BITS = 300000` бит при умножении/степени, `MAX_SEQ_RESULT =
  10 000 000` при повторении строк и списков.
* **Вызовы** (`call_value`): `QFunction`/`BoundMethod` → `call_function` (разбор позиционных, именованных, `*`/`**`
  параметров); `Builtin` → проверка арности, привязка именованных (`kw`/`kwonly`), вызов `fn(interp, *args)`;
  `BoundBuiltin` (метод встроенного типа); `QClass` → `instantiate` (создать `QInstance`, вызвать `жасау`).
* **Исключения Python внутри встроенных функций** (`ValueError`, `OverflowError`, …) превращаются в ошибки Qazaq
  в `_call_native` вида ««имя»: Тип: текст» — поэтому встроенные функции обязаны проверять аргументы **сами** и
  выдавать понятные сообщения заранее.
* **Режимы:** `safe=True` (Playground) отключает функции с `unsafe=True` (`оқы`, `сақта`, `сыз`); `echo=True` (REPL)
  печатает значение инструкции-выражения.
* **`eval`/`exec` не используются нигде** — это проверяет `tests/test_integration.py` (поиск по исходникам).

### 5.6. Значения и стандартная библиотека

* Значения Qazaq — обычные значения Python (см. 4.3) плюс классы из `runtime.py` (`QFunction`, `QClass`, `QInstance`,
  `BoundMethod`, `Builtin`, `BoundBuiltin`, `QSet`). Представление: `to_repr` (как в коде, строки в кавычках, циклические
  ссылки `[…]`) и `to_str`; `type_name` даёт имя типа по-казахски.
* **Реестр** (`qaz/stdlib/registry.py`): декоратор `@builtin(имя, мин_арг, макс_арг, category=…, sig=…, doc=…, kw=…, kwonly=…,
  unsafe=…)` кладёт функцию в `BUILTINS`; `@method(тип_Python, имя, мин, макс, sig=…, doc=…)` — в `METHODS[тип]`;
  `alias(новое, старое)` — синоним; `CONSTANTS` — константы (`пи`). Помощники `expect_number/expect_int/expect_str/as_list/
  numbers/rt_error` делают проверки с понятными сообщениями. **Сигнатура всех функций:** `fn(interp, *аргументы)`; у
  метода первым аргументом после `interp` идёт сам объект.
* Файлы: `core.py` (ввод-вывод, типы, коллекции, строки/списки/словари/множества), `mathlib.py` (математика,
  `кездейсоқ`, `тұқым`), `data.py` (`талда`, `үйрет`, `болжа`), `science.py` (`шеш`, `туын`, `интегр`, `сыз` — SymPy и
  Matplotlib **подключаются лениво**, только когда функция вызвана), `io_lib.py` (`оқы`, `сақта`).
* **Детерминизм:** сумма дробных — точная (`math.fsum`), дисперсия — через дроби; генератор случайных чисел — Mersenne
  Twister, как в Python (`тұқым(42)` даёт одинаковое на сайте и локально).

### 5.7. Ошибки и казахские сообщения

* **Классы** (`qaz/errors.py`): `QazaqError` (поля `message`, `line`, `col`, `hint`, `trace`, `filename`; `catchable`),
  `LexicalError`, `QazaqSyntaxError`, `QazaqRuntimeError` (ловится), `ResourceLimitError` (не ловится). `format_error(err,
  source, filename, lang)` печатает заголовок, место, строку кода с `^`, цепочку вызовов (длинную сокращает до «… ещё N
  вызовов …») и подсказку.
* **Принцип перевода:** интерпретатор **всегда** формирует сообщение по-русски — так его одинаково видит программа
  внутри `қате е:` и все тесты. Казахский вариант получается **только при показе**: `qaz.messages.translate()` (Python) и
  `translateText()` (JS, `site/src/engine/00_messages.js`) сопоставляют текст с **шаблонами** из `qaz/messages_kk.json`.
* **Шаблон** — русский текст с местами `{имя}`: `"Индекс {i} вне диапазона (длина {n})"` → `"{i} индексі ауқымнан тыс
  (ұзындығы {n})"`. Совпадение — по полному тексту (регулярное выражение из шаблона, `{имя}` → `[\s\S]+?`); **первое
  совпавшее правило побеждает**, поэтому частные правила стоят перед общими (тест `test_no_rule_is_shadowed…`). Значения
  `{want}`/`{got}` дополнительно переводятся списком `fragments` (например, «конец строки» → «жол соңы»).
  Не нашлось — сообщение показывается как есть (без поломки).
* **Тесты каталога** (`tests/test_messages.py`): (1) разбором исходников через `ast` находит **все** места, где создаются
  ошибки, и требует, чтобы у каждого был перевод; (2) ни одно правило не перекрыто более ранним; (3) **Python и JS переводят
  весь корпус программ одинаково**. Если вы добавляете сообщение, тест подскажет, что нужно добавить в каталог.
* ⚠ Тексты каталога **не проверены носителем**. Их таблица — `docs/KAZAKH_MESSAGES_REVIEW.md`.

### 5.8. Командная строка, REPL, раннер

* `qaz/cli.py`: подкоманды `run`, `check`, `repl`, `version`, `help`; `qaz файл.qaz` = `qaz run файл.qaz`. Коды возврата: 0 успех,
  1 ошибка программы, 2 неверное использование, 130 Ctrl+C. Язык ошибок: `--lang ru|kk` или переменная `QAZAQ_LANG`.
* `qaz/repl.py`: построчный режим; блок, начатый двоеточием, ждёт продолжения.
* `qaz/runner.py`: `execute(payload)` — одноразовый запуск для серверного режима: JSON `{code, stdin, timeout, max_steps,
  max_output, max_depth, lang}` → JSON `{status: ok|error|limit, stdout, error, steps}`. Его же используют тесты соответствия.
