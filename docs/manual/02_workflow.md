## 2. Среда и рабочий процесс

### 2.1. Среда, в которой создавался проект

| Что | Значение |
|---|---|
| Где идёт работа | облачный контейнер Claude Code (Linux), репозиторий в `/home/user/kazakhmur` |
| Python | 3.13 (проект поддерживает `>=3.10`; ядро не требует сторонних пакетов) |
| Node.js | 22 (нужен только для тестов сайта, сборка сайта — на чистом Python) |
| Установлено | `pytest`, `sympy`, `matplotlib`, `fastapi`, `uvicorn`, `httpx`, `build`; Chromium + Playwright (предустановлены); глобально в npm — `axe-core` |
| Сеть | исходящий трафик идёт через прокси; многие внешние хосты недоступны. Тесты сайта работают **без сети** (все запросы кроме `file:`/`data:`/`blob:` обрываются — это сделано намеренно) |

### 2.2. Команды (всё запускать из корня репозитория)

▶ **Полный набор проверок** (занимает 2–4 минуты; для браузерных тестов нужен `NODE_PATH`):

```bash
export NODE_PATH="$(npm root -g)"        # чтобы Node нашёл playwright и axe-core
python3 -m pytest                        # все тесты (код возврата 0 = всё хорошо)
```

⚠ **Ловушка с `-q`.** В `pyproject.toml` уже стоит `addopts = "-q"`. Если добавить свой `-q`, итоговая строка
«N passed» **не печатается** (остаются только точки). Смотрите код возврата (`echo $?`) или запускайте без `-q`.

▶ **Сборка сайта** (обязательна перед любыми тестами сайта и публикацией):

```bash
python3 scripts/build_site.py            # создаёт site/dist/{index.html, fragment.html, engine.js, language.json}
```

▶ **Отдельные проверки сайта:**

```bash
node site/test/e2e.js                    # сквозной сценарий в настоящем Chromium (≈ 12 шагов)
node site/test/a11y.js                   # axe-core: WCAG 2 A/AA, светлая/тёмная тема, десктоп/телефон, все вкладки и книга
node site/test/perf.js                   # бюджет: вес, FCP, LCP, CLS, долгие задачи (процессор ×4 медленнее)
E2E_VERBOSE=1 node site/test/e2e.js      # то же с названиями шагов
```

▶ **Генерируемые файлы** (после изменений, которые их затрагивают):

```bash
python3 scripts/gen_stdlib_doc.py        # docs/STANDARD_LIBRARY.md ← реестр функций
python3 scripts/gen_manual.py            # docs/MANUAL.md и docs/KAZAKH_MESSAGES_REVIEW.md
python3 scripts/make_manual_html.py      # site/dist/manual.html — веб-страница руководства (pip install markdown)
node scripts/make_manual_pdf.js          # docs/MANUAL.pdf — печать веб-версии (после предыдущей команды)
python3 scripts/make_archive.py          # archive_out/qazaq-full-archive.zip — архив «всё о проекте» (руководства, сайт, код с историей git, ссылки, промпт для ИИ)
node scripts/make_book_pdf.js            # docs/QAZAQ_BOOK.pdf ← раздел «Книга» (нужен собранный сайт)
```

▶ **Запуск языка локально:**

```bash
python3 -m qaz run examples/01_hello.qaz            # без установки пакета
python3 -m qaz run examples/06_errors.qaz --lang kk # ошибки по-казахски
python3 -m qaz repl                                 # интерактивный режим
pip install -e .                                    # даст команду `qaz`
```

▶ **Серверный режим** (необязателен): `pip install -e ".[server,science]"`, затем
`python3 -m uvicorn backend.app:app --host 127.0.0.1 --port 8000`.

### 2.3. Цикл работы над любой задачей

1. **Прочитать нужные файлы** (не угадывать). Карта — глава 3; рецепты — глава 11.
2. **Изменить код.** Если это язык или библиотека — **в обоих движках сразу** (Python и JS), иначе тест
   соответствия упадёт (глава 6).
3. **Добавить проверки:** юнит-тесты на Python и, для поведения языка, программы в `tests/conformance_corpus.py`.
4. **Запустить**: сначала узкий тест (`python3 -m pytest tests/test_xxx.py`), потом полный набор.
5. **Обновить документацию** (SYNTAX/GRAMMAR/ROADMAP/CHANGELOG, при необходимости книгу) и сгенерировать
   производные файлы (см. выше).
6. **Коммит и пуш** в `claude/qazaq-lang`; **публикация сайта** в Artifact (если менялся сайт); короткий отчёт.

### 2.4. Git: правила

* Работать только в ветке `claude/qazaq-lang`. Пуш: `git push -u origin claude/qazaq-lang`
  (при сетевой ошибке повторить до четырёх раз с паузой).
* **Не пушить в `main`, не создавать Pull Request, не удалять ветки без явного разрешения владельца.**
  Попытка `git push origin …:main` была заблокирована классификатором безопасности — это **не** ошибка, которую
  надо обходить; нужно сообщить владельцу и спросить.
* Сообщение коммита — по-русски, первая строка — суть, дальше маркированный список. Строки-атрибуция в конце
  сообщения добавляются так, как укажет среда (в этой сессии: `Co-Authored-By: …` и `Claude-Session: …`).
* Не коммитить секреты (`.env`, токены). В проекте их нет.
* ⚠ **PDF весит ≈ 1 МБ.** Каждый коммит с перегенерированным `docs/QAZAQ_BOOK.pdf` добавляет мегабайт в историю.
  Перегенерируйте PDF, только когда изменился текст книги.

### 2.5. Публикация сайта в Artifact

Сайт публикуется как приватная страница в claude.ai (только владелец видит ссылку, пока не нажмёт Share).

1. `python3 scripts/build_site.py`.
2. Инструмент **Artifact**: `action: publish`, `url: https://claude.ai/artifact/SXdTbbowEAk2mDLHuC1hKL`,
   `file_path: /home/user/kazakhmur/site/dist/fragment.html`, `label: «краткое описание версии»`.
   Файл `fragment.html` — это страница без `<html>/<head>/<body>` (так требует Artifact); `index.html` — полная версия
   для обычного хостинга.
3. Версия растёт сама (на момент передачи — 11). Ссылка не меняется.

### 2.6. Продолжение работы «само по себе»

Владелец попросил: «после окончания лимитов жди и автоматически начинай как только они обновятся». Для этого
используется инструмент отложенных сообщений: `send_later` (одноразово) или `update_trigger` для уже созданного
напоминания `trig_01FnL5Aat9Xx1nukFbhSBQeq`. В тексте напоминания лежит **самодостаточный** список задач — он должен
быть понятен без контекста беседы (сессия «просыпается» с тем же диалогом, но лучше не рассчитывать на память).
Правила: в конце каждого цикла ставить следующее напоминание, если работа не завершена; не ставить его, если
остались только решения владельца.

### 2.7. Что запрещено делать без спроса

| Действие | Почему |
|---|---|
| Пуш в `main`, создание PR, force-push | решение владельца; классификатор безопасности блокирует |
| Публикация серверного Playground в интернет | нет контейнерной изоляции (см. `docs/SECURITY.md`) |
| Выдавать казахские тексты за проверенные | их не проверял носитель языка |
| Менять философию языка (точка, отступы, слова) | это решает владелец; он уже принял: точка-завершитель, отступы, оба написания слов, комментарии `;`, режим `[ ]` |
| Отключать/ослаблять тесты ради «зелёного» | прямой запрет задания |

### 2.8. Типичные ловушки окружения

* ⚠ `python` может отсутствовать — используйте `python3`.
* ⚠ Тесты сайта нужно запускать **после** `build_site.py`; `tests/test_site.py` делает это сам, но
  `node site/test/*.js` напрямую — нет.
* ⚠ `tests/test_conformance.py` пересобирает сайт (нужен для `engine.js`) и запускает Node; без Node тесты
  помечаются как пропущенные (`skipif`), а не падают.
* ⚠ Файл `qaz/lexer.py` содержит один символ BOM в строке `startswith` (так задумано; не «чините»).
* ⚠ `site/src/book.json` и `site/src/tour.json` — **источники** текста; правятся вручную. Они хранятся с отступом в
  1 пробел; при правке из скрипта используйте `json.dump(..., ensure_ascii=False, indent=1)`, иначе diff будет огромным.
* ⚠ Числа в тексте книги (количество функций/методов) подставляются при сборке из меток `{{N_BUILTINS}}`,
  `{{W_FUNCS}}` и т. п. — не заменяйте их цифрами.
* ⚠ После изменения реестра функций нужно перегенерировать `docs/STANDARD_LIBRARY.md`, иначе упадёт
  `tests/test_docs.py::test_stdlib_reference_is_up_to_date`.
* ⚠ Блоки кода ```` ```qaz ```` и ```` ```qaz-run ```` в **любых** файлах `docs/*.md` и `README.md` исполняются
  тестами (`tests/test_docs.py`) и сравниваются в обоих движках (`tests/test_conformance.py`). Для текста, который
  не должен исполняться, используйте ```` ```text ````.
