## 12. Принятые решения и их причины

Формат: **решение** — почему — какие были альтернативы — чем платим. Эти решения нельзя менять «между делом»: часть из них — воля
владельца (отмечено 👤), часть — инженерный выбор исполнителя (🛠).

| № | Решение | Почему | Альтернативы | Цена / последствия |
|---|---|---|---|---|
| 1 | 👤 **Интерпретатор на Python** (первая версия) | прямое требование задания; быстрее всего довести до рабочего состояния | Rust/Go/C++ | скорость «как у интерпретатора на Python» (сотни тысяч инструкций в секунду) |
| 2 | 👤 **Точка завершает инструкцию**; заголовки блоков — двоеточие | главная особенность языка | точка с запятой, перевод строки | нужно правило точки (цифры/конец/член) и правило «NL только после точки или двоеточия» — оно же позволяет переносить выражения без скобок |
| 3 | 👤 **Блоки отступами**, табуляция = 4 пробела | ориентир — Python, меньше «шума» | фигурные скобки | ошибки отступа понятны, но чувствительны к пробелам |
| 4 | 👤 **Слова-кандидаты из задания оставлены как есть**; полные написания принимаются **наравне** (`айнымалы`, `функция`, `туынды`, `интеграл`) | владелец ответил «принимай оба написания»; естественность и краткость одновременно | заменить на полные; оставить только краткие | лексер нормализует синонимы; парсер о них не знает |
| 5 | 🛠 **NFC для идентификаторов** и запрет смешения латиницы и кириллицы в одном слове | «і» (казахская) и `i` (латинская) выглядят одинаково — иначе ошибки неуловимы | молча принимать | отдельное понятное сообщение с номером символа |
| 6 | 🛠 **Язык как данные** (`tokens.py` + реестр функций → `language.json`) | подсветка, автодополнение, каталог, справочник и самопроверка JS не расходятся с интерпретатором | таблицы в каждом месте | JS-движок обязан реализовать всё из реестра (иначе падает при старте) |
| 7 | 🛠 **JS-порт интерпретатора для сайта** | сайт без сервера, мгновенный старт, безопасно для хостинга, один лёгкий файл | сервер; Pyodide | два движка надо держать равными (решение 8) |
| 8 | 🛠 **Дифференциальное тестирование** как главная гарантия равенства движков | любой дефект виден как расхождение; не нужно «знать правильный ответ» заранее | ручные тесты на каждый случай | корпус растёт; новая возможность = программы в корпус |
| 9 | 🛠 **Сайт — один HTML без библиотек**, собственный редактор (прозрачный `textarea` поверх подсветки) | работает офлайн и на любом хостинге; нет сборки npm; полный контроль над поведением и размером | React + Monaco (так было в первой версии, затем заменено) | автодополнение, отступы, скобки — написаны вручную; нет многокурсорности и т. п. |
| 10 | 🛠 **Безопасность: сначала браузер**, сервер — необязательный и «не для интернета без контейнера» | честная граница: код посетителя не покидает его устройство | публичный сервер | серверный режим ограничен доверенной сетью |
| 11 | 🛠 **Сообщения об ошибках всегда по-русски внутри**, перевод — при показе, по каталогу шаблонов, общему для Python и JS | программа внутри `қате е:` и тесты видят один текст; перевод можно править без кода | менять сообщения в 170 местах кода; хранить казахский как основной | сопоставление по шаблонам (порядок правил важен); тесты полноты |
| 12 | 👤 **Казахские сообщения — переключатель** (русские по умолчанию) | владелец выбрал вариант «сделать переключатели» | только русские; казахские основные | тексты ждут проверки носителем |
| 13 | 👤 **Комментарий `;`** (и `#`), три конца `. ? !`, знаки `× ÷ ≤ ≥ ≠`, конвейер `\|>`, условное выражение, **режим квадратных скобок** | владелец просил «фичи с особым характером, но понятные» | оставить минимальный синтаксис | больше правил в лексере; всё покрыто корпусом |
| 14 | 🛠 **Режим «шаршы жақша» — подмена скобок в лексере**, а не отдельный синтаксис | парсер и интерпретатор не знают о режиме — ноль лишней сложности | отдельная грамматика | режим включается директивой в начале файла или параметром лексера |
| 15 | 🛠 **`жиын` создаётся функцией, без литерала; порядок — по добавлению** | `{1, 2}` конфликтует со словарём; порядок хеша Python недетерминирован между запусками, а Qazaq обязан быть детерминированным | `set` Python как есть | repr вида `жиын([1, 2])` (читается и разбирается) |
| 16 | 🛠 **`*остальные` → кортеж, `**именованные` → словарь** | как в Python; кортеж подчёркивает неизменяемость | список | `*` и `**` — только в конце параметров |
| 17 | 🛠 **`кілт=` и подобное — «только по имени» (`kwonly`)** у встроенных | у `минимум(a, b, c)` нет места для позиционного «ключа»; именованный параметр однозначен | третий позиционный | в JS такие функции получают объект параметров последним аргументом |
| 18 | 🛠 **Целые — `BigInt`, формат дробных и округление — точные** | вывод на сайте должен совпадать с `qaz run` до последней цифры | `number` и `toFixed` | собственная реализация форматов и математики (`03b_hpmath.js`) |
| 19 | 🛠 **Символьная математика в браузере — только многочлены**, вывод по правилам SymPy, сверка с SymPy на сотнях случайных примеров | честный объём вместо «почти работает»; остальное — понятное «нужен локальный Qazaq» | не поддерживать; портировать SymPy | ≈ 20 % случайных уравнений браузер не берёт |
| 20 | 🛠 **«Шаги» — только в JS-движке** (хук `onStep`) | нужны только сайту; в Python был бы лишний хук на горячем пути | реализовать и в Python | в `qaz run` отладчика нет |
| 21 | 🛠 **Книга — данные (`book.json`) + один рендерер; PDF — печать той же страницы** | один источник правды; печатная и интерактивная версии не расходятся | отдельный PDF-документ | русский текст; PDF весит 1 МБ |
| 22 | 🛠 **Доступность и скорость — тесты с бюджетами** | «приятно работать и всё понятно читать» — требование владельца; регрессии ловятся автоматически | ручной аудит | нужны Playwright и axe-core |
| 23 | 👤 **В `main` и PR — только с разрешения** | воля владельца; в среде пуш в `main` заблокирован | автоматическое слияние | нужна явная команда |
| 24 | 🛠 **Не добавлять методы «на месте» вроде `список.сұрыпта()`** | было бы путаницей с функцией `сұрып(список)`, которая возвращает копию; методы встроенных не принимают именованных аргументов | добавить | сортировка — через `список = сұрып(список)` (открытый вопрос, глава 15) |
| 25 | 🛠 **Названия `сандық`, `әріптік`, `толтыр`, `жолдар`, `топта` придуманы исполнителем** (владелец разрешил решать самому: «сделай как считаешь нужным») | нужны были базовые строковые операции и группировка (из исходного задания: «Data: группировка») | ждать согласования | названия могут оказаться неудачными с точки зрения носителя; замена — правка одного слова в Python-реестре и одного в JS (плюс каталог сообщений и документация) |
